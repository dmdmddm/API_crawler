# LLM API 가격 모니터

주요 대형 언어모델(LLM) 제공사의 **공식 API 가격을 매일 자동 수집**하고, 전날 대비 **변동을 감지·강조**해서 **웹 대시보드**로 보여주는 도구입니다. 각 제공사 공식 페이지에서 직접 수집하며 제3자 집계 서비스에 의존하지 않습니다.

설치 경로는 아래 예시에서 `/path/to/api_crawler` 로 적습니다. 자기 환경 경로로 바꿔 쓰세요.

## 수집 대상 (현재 6개)

| 제공사 | 소스 | 수집 방식 |
|--------|------|-----------|
| Anthropic (Claude) | docs.claude.com 가격 | HTML 표 (기본 표 + 배치 표 병합) |
| OpenAI (GPT) | platform.openai.com 문서 | HTML 표 (등급 4벌 × 컨텍스트 구간 2벌) |
| Google (Gemini) | ai.google.dev | HTML 표 (모델별 표가 등급 4벌 반복) |
| xAI (Grok) | docs.x.ai 가격 | HTML 표 + 모델 목록 JSON 교차 대조 |
| Perplexity (Sonar) | docs.perplexity.ai | HTML 표 |
| DeepSeek | api-docs.deepseek.com | HTML 표 (모델이 열인 전치 구조) |

가격 단위는 전부 **100만 토큰당 USD**로 정규화합니다. 받는 단가는 6종입니다.

| 항목 | Anthropic | OpenAI | Google | xAI | Perplexity | DeepSeek |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| 입력 · 출력 | O | O | O | O | O | O |
| 캐시 읽기 | O | O | O | O | - | O |
| 캐시 쓰기 | O | O | - | - | - | - |
| 배치 입력 · 출력 | O | O | O | O | - | - |

"-"는 그 제공사가 공식 페이지에 아예 공개하지 않는 항목입니다. 회사별 수집 코드마다 `available_fields`로 "공개하는 항목"을 적어 두어, 공개하는데 값이 비면 파서가 놓친 것으로 보고 경고를 냅니다.

xAI는 배치 단가를 금액이 아니라 할인율로만 적어 두기 때문에(2026-07 기준 20%), 표준 단가에 할인율을 적용해 계산하고 원문 조각을 함께 남깁니다.

등급(Standard / Batch / Flex / Priority) 중 표준과 배치만 저장합니다. Flex는 배치와 같은 값이고, Priority는 할인이 아니라 할증이라 마진 계산 성격이 다릅니다. 컨텍스트 구간이 나뉘는 곳(OpenAI·xAI)은 짧은 구간을 저장하며, 레코드에 그 사실을 적어 둡니다.

## 설치

```bash
cd /path/to/api_crawler
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

## 실행

```bash
cd /path/to/api_crawler
.venv/bin/python run.py              # 오늘 날짜로 실시간 수집 → 스냅샷·대시보드 생성
.venv/bin/python run.py --offline    # 저장된 페이지 사본으로 수집(아래 주의 참고)
.venv/bin/python run.py --date 2026-07-15      # 특정 날짜로 저장
.venv/bin/python run.py --rebuild 2026-07-27   # 재수집 없이 화면만 다시 그림
```

> **주의**: `--offline`과 `test_adapters.py`는 `data/pages/YYYY-MM-DD/`에 그날 받아 둔 6개사 페이지가 있어야 돕니다. 읽는 날짜는 `pages.py`의 `FIXTURE_DATE` 한 줄로 정합니다. 그 폴더는 남의 페이지를 통째로 담는 것이라 저장소에 넣지 않았습니다. 받은 직후에는 `run.py`로 실제 수집을 한 번 하고 `FIXTURE_DATE`를 그날로 맞춰야 하며, `--offline`은 그 전까지 실패합니다.

실행하면 다음이 생성됩니다.
- `data/snapshots/YYYY-MM-DD.json`: 그날의 전체 가격 스냅샷(정본 저장소)
- `data/changes/YYYY-MM-DD.json`: 직전 수집 대비 변동 목록
- `public/index.html`: 자족형 대시보드(외부 리소스 없이 단일 파일)
- `data/snapshots/archive/`: 비교 대상에서 뺀 옛 스냅샷(파일은 보존)

같은 시각에 두 번 도는 것을 파일 잠금으로 막고, 제공사별로 3회까지 재시도합니다.

확인할 일이 있으면 화면 맨 위에 항목이 나열되고 알림 메일이 나갑니다. 종료 코드는 자리별 비트를 더한 값이라 여러 개면 합으로 나옵니다(예: 9 = 1 + 8).

| 값 | 뜻 | 값 | 뜻 |
|---|---|---|---|
| 1 | 큰 변동(직전 대비 2배 이상) | 16 | 모델 사라짐 |
| 2 | 수집 실패(연결 안 됨) | 32 | DB 넣기 실패 |
| 4 | 0개 파싱(응답은 받았는데 한 건도 못 뽑음) | 64 | 수집 코드 경고 |
| 8 | 아는 모델이 안 옴 | 128 | 중복 실행 차단 |

```bash

```

## 동작 원리

1. **수집**: `adapters/`의 제공사별 수집 코드가 각 공식 페이지를 파싱. 하나가 깨져도 나머지는 계속 수집. 페이지의 관련 표를 전부 읽은 뒤 무엇인지 식별해서 맞는 것만 저장합니다("첫 표만 취해서 우연히 맞는" 상황을 없애기 위함).
2. **저장**: 날짜별 JSON 스냅샷으로 남김. 수집에 실패한 제공사는 직전 값으로 채우지 않고 실패로 기록합니다.
3. **변동 감지**: 오늘 스냅샷 vs **직전 성공 수집분**을 비교 → 추가/삭제/단가 변경. 비교 단위는 모델이 아니라 제공사·모델·등급·컨텍스트 구간·적용 시기입니다. 같은 모델의 표준 행과 배치 행이 하나로 뭉개지지 않게 하기 위함입니다. 그날 실패한 제공사는 비교에서 통째로 제외합니다(실패를 "모델이 사라졌다"로 기록하지 않도록).
4. **대시보드**: 제공사별 표 + 변동 강조 배지 + 변경 이력 + 수집 상태. 표에는 입력·출력만 싣고 캐시·배치 단가는 모델명을 펼치면 나옵니다. 회사별 주력 모델만 기본 표시하고 나머지는 접습니다(주력 목록 = `dashboard.py`의 `FEATURED`). 값이 바뀌었거나 새로 등록된 모델은 목록에 없어도 접지 않습니다.
5. **알림**: 변동 시 콘솔 출력. 이메일/슬랙 연동은 `run.py`의 `notify()`에 연결.

각 회사별 수집 코드에는 **sanity 체크**가 있어 페이지 개편으로 수집이 깨지면 경고로 드러납니다. 점검 항목은 최소 모델 수, 가격 범위, 그리고 "공개한다고 적어 둔 항목이 전 모델에서 비었는가"입니다.

## 가격 검증 (온디맨드 적대적 감사)

`audit.py`는 공식 페이지를 다시 읽어 우리 수집값을 **반박 시도(adversarial)**합니다. 집계 서비스(경쟁사) 대신 각 제공사 공식 페이지를 근거로, LLM(Codex)이 **기억이 아니라 원문에서** 단가를 독립 재추출해 우리 값과 대조합니다. 앵커링(우리 값에 끌려가기)을 막으려고 우리 값은 LLM에 주지 않습니다.

```bash
.venv/bin/python audit.py --offline --provider DeepSeek   # 특정 제공사
.venv/bin/python audit.py --limit 5                       # 상위 5건(라이브)
```

판정: 확인(우리값과 일치) / 반박(다름 → 검토 필요) / 불명확 / 건너뜀. 결과는 `data/audits/YYYY-MM-DD.json`에 저장됩니다. LLM 비용·의존 때문에 매일 자동 루프에는 넣지 않고 필요할 때 실행합니다. 백엔드는 Codex CLI이며, `codex_extract()`만 바꾸면 독립 Claude 에이전트 등으로 교체할 수 있습니다.

가격이 바뀐 날에는 자동으로 근거를 남깁니다. 그날 받아 둔 공식 페이지에서 모델 이름 주변 원문을 오려내 `data/excerpts/YYYY-MM-DD.json`에 저장하고, 전날 같은 자리와 대조합니다. **원문이 그대로인데 값만 바뀌었으면 파서 오류로 의심**해 확인 필요에 올립니다. 파서를 안 거치고 글자만 찾아 오려내므로 표 고르기가 틀려도 이 경로는 끌려가지 않습니다. 알림 메일에는 변동이 있던 회사의 공식 페이지 주소가 함께 나갑니다.

참고: 외부 집계 서비스(OpenRouter·LiteLLM) 대조는 2026-08-10에 폐기했습니다. 두 곳 모두 **가격이 며칠자인지를 공개하지 않아**, 값이 어긋났을 때 우리가 틀렸는지 저쪽이 낡았는지 판정할 수 없습니다. 판정할 수 없는 대조는 경보로 쓸 수 없습니다.

## 매일 자동 실행 (cron)

등록 예시는 `crontab.example.txt`에 있습니다. 경로를 자기 환경에 맞게 고쳐 `crontab.txt`로 복사한 뒤 등록합니다(`crontab.txt`는 기계마다 경로가 달라 저장소에 넣지 않습니다).

```cron
# 매일 한국시간 00:30 수집 (서버 시간대가 Asia/Seoul이라 그대로 KST)
30 0 * * * /path/to/api_crawler/.venv/bin/python /path/to/api_crawler/run.py >> /path/to/api_crawler/data/run.log 2>&1
```

```bash
cp crontab.example.txt crontab.txt         # 경로를 고친 뒤
crontab /path/to/api_crawler/crontab.txt   # 등록
crontab -l                                 # 확인
```

cron은 실패해도 다시 걸어주지 않으므로 재시도는 `run.py` 안에서 합니다. 절대 경로로 적는 이유는 cron이 로그인 셸과 다른 환경에서 돌기 때문입니다.

## 웹에 올리기

화면 파일을 사람이 보내면 받은 사람은 보낸 날 값에 멈춥니다(파일 안에 그날 값이 박혀 있고, 열 때 인터넷에서 새로 가져오지 않습니다). 주소로 보게 하려면 `publish.py`로 `gh-pages` 갈래에 올립니다.

```bash
.venv/bin/python publish.py --setup     # gh-pages 갈래를 만든다(한 번만)
.venv/bin/python publish.py             # 오늘 화면을 올린다
.venv/bin/python publish.py --dry-run   # 커밋·푸시 없이 준비만
```

- `--setup`을 한 번 해 두면 `run.py`가 매일 수집 뒤 자동으로 올립니다. 안 해 둔 기계에서는 아무 일도 일어나지 않습니다.
- 올리기 실패는 수집 실패로 치지 않습니다. 값은 이미 저장본과 DB에 들어가 있고 나중에 `publish.py 날짜`로 다시 올릴 수 있습니다.
- `main`은 코드·문서, `gh-pages`는 화면 파일만 담습니다. 매일 바뀌는 파일이 코드 이력에 섞이지 않게 `--orphan`으로 만들어 둘을 합치지 않습니다.
- 검색 결과에는 안 뜨게 두 겹으로 막습니다. 화면 파일 안의 `noindex` 표시와 `robots.txt`입니다. 주소를 아는 사람은 그대로 볼 수 있습니다.

## 웹페이지 연동

`public/index.html`은 외부 의존성 없는 단일 파일이라 그대로 사용할 수 있습니다.
- 정적 호스팅(nginx로 `public/` 서빙)
- 사내 페이지에 iframe 삽입 또는 본문 삽입
- `dashboard.render_body()`는 본문 조각(스타일+마크업)만 반환하므로 기존 페이지 템플릿에 직접 끼워 넣을 수 있음

## 새 제공사 추가

1. `adapters/<name>.py`에 `BaseAdapter` 상속 클래스 작성 (`parse(html)` 구현).
2. `adapters/registry.py`의 `ALL_ADAPTERS`에 등록.
3. 오프라인 테스트는 `run.py`로 한 번 수집해 `data/pages/`에 페이지를 남긴 뒤 `test_adapters.py`로 검증.

> `data/pages/`(매일 받은 6개사 페이지)와 매일 수집한 값은 저장소에 넣지 않습니다. 남의 페이지를 통째로 담는 것이라서입니다. 따라서 저장소를 받은 뒤 바로 `run.py --offline`이나 `test_adapters.py`를 돌릴 수는 없고, `run.py`로 한 번 실제 수집을 해야 합니다.

## 한계와 주의

- 공식 페이지 구조에 의존하므로 **페이지 개편 시 해당 회사 수집 코드만 조정**이 필요할 수 있습니다(sanity 경고로 감지됨). 실제로 2026-07-27에 xAI가 내부 데이터 형식을 바꿔 그 회사 수집 코드가 조용히 0개를 수집하고 있던 것을 발견했습니다. 지금은 공식 가격표와 모델 목록 두 곳을 교차 대조합니다.
- 화면의 주력 모델 목록은 새 모델이 나오면 손으로 갱신해야 합니다. 새 모델은 등록된 날 화면에 뜨므로 그때 추가하면 됩니다.
- Gemini 페이지에는 이미지/음성(TTS) 모델도 포함됩니다. 토큰이 아닌 단위(이미지 장당 등)의 값은 파싱 단계에서 제외되어 해당 칸이 비어 보입니다(2026-07-20부터).
